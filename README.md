# NoteFlame

**Share secrets that self-destruct.** Encrypted, ephemeral message sharing.

Send passwords, API keys, and sensitive messages that disappear after being read. AES-256-GCM encrypted. No trace left behind.

## Features

- **AES-256-GCM Encryption** - Content is encrypted before storage; the key never touches the database
- **Burn After Reading** - Drops are permanently destroyed after the configured number of views
- **Auto-Expiry** - Set drops to expire in 1 hour, 24 hours, 7 days, or 30 days
- **Password Protection** (Pro) - Add an extra layer of security
- **REST API** (Pro) - Create and retrieve drops programmatically
- **Burn Notifications** - Get notified when your drop is opened
- **Dashboard** - Track and manage all your drops
- **Stripe Billing** - Built-in subscription management

## Deploy to Render (Easiest)

### One-Click Deploy

1. Push this repo to your GitHub account
2. Go to [Render Dashboard](https://dashboard.render.com)
3. Click **New → Blueprint**
4. Connect your GitHub repo
5. Render will auto-detect `render.yaml` and create:
   - A web service
   - A PostgreSQL database
6. Set the remaining environment variables (see below)
7. Done! Your app is live.

### Environment Variables to Set on Render

After the Blueprint deploys, go to your web service → Environment and add:

| Variable | Value | Notes |
|----------|-------|-------|
| `STRIPE_SECRET_KEY` | `sk_live_...` | From Stripe Dashboard → API Keys |
| `STRIPE_PUBLISHABLE_KEY` | `pk_live_...` | From Stripe Dashboard → API Keys |
| `STRIPE_WEBHOOK_SECRET` | `whsec_...` | See Stripe Webhook Setup below |
| `STRIPE_PRO_PRICE_ID` | `price_...` | See Stripe Product Setup below |
| `STRIPE_BUSINESS_PRICE_ID` | `price_...` | See Stripe Product Setup below |
| `APP_URL` | `https://your-app.onrender.com` | Your Render URL |

> `DATABASE_URL`, `SESSION_SECRET`, and `ENCRYPTION_SECRET` are auto-generated by render.yaml.

## Stripe Setup (15 minutes)

### 1. Create a Stripe Account
- Go to [stripe.com](https://stripe.com) and sign up
- Complete account verification

### 2. Create Products
In Stripe Dashboard → Products → Add Product:

**Product 1: NoteFlame Pro**
- Name: `NoteFlame Pro`
- Price: `$8.00/month` (recurring)
- Copy the **Price ID** (starts with `price_`) → use as `STRIPE_PRO_PRICE_ID`

**Product 2: NoteFlame Business**
- Name: `NoteFlame Business`
- Price: `$24.00/month` (recurring)
- Copy the **Price ID** → use as `STRIPE_BUSINESS_PRICE_ID`

### 3. Get API Keys
- Stripe Dashboard → Developers → API Keys
- Copy **Publishable key** → `STRIPE_PUBLISHABLE_KEY`
- Copy **Secret key** → `STRIPE_SECRET_KEY`

### 4. Set Up Webhook
- Stripe Dashboard → Developers → Webhooks → Add endpoint
- URL: `https://your-app.onrender.com/webhooks/stripe`
- Events to listen for:
  - `checkout.session.completed`
  - `customer.subscription.updated`
  - `customer.subscription.deleted`
- Copy the **Signing secret** → `STRIPE_WEBHOOK_SECRET`

## Local Development

### Prerequisites
- Node.js 18+
- PostgreSQL (local or use free [Neon](https://neon.tech) database)

### Setup

```bash
# Clone the repo
git clone <your-repo-url>
cd noteflame

# Install dependencies
npm install

# Copy environment file and edit it
cp .env.example .env
# Edit .env with your database URL and secrets

# Initialize the database
npm run db:init

# Start the server
npm start

# Or with auto-reload for development
npm run dev
```

Visit `http://localhost:3000`

### Using Neon (Free PostgreSQL)

If you don't want to install PostgreSQL locally:

1. Sign up at [neon.tech](https://neon.tech) (free tier: 0.5GB storage)
2. Create a project and database
3. Copy the connection string to `DATABASE_URL` in your `.env`

## Tech Stack

- **Runtime**: Node.js 18+
- **Framework**: Express.js
- **Database**: PostgreSQL
- **Templates**: EJS
- **CSS**: Tailwind CSS (CDN) + custom dark theme
- **Auth**: bcrypt + cookie-session
- **Encryption**: AES-256-GCM (Node.js crypto)
- **Payments**: Stripe Checkout + Webhooks
- **Scheduling**: node-cron (cleanup expired drops)

## API Usage

See `/api-docs` on your deployed instance, or check `routes/api.js` for the full API.

Quick example:

```bash
# Create a drop
curl -X POST https://your-app.com/api/drops \
  -H "Authorization: Bearer $(echo -n 'you@email.com:password' | base64)" \
  -H "Content-Type: application/json" \
  -d '{"content": "my-secret", "expiry_hours": 24}'

# View a drop
curl https://your-app.com/api/drops/YOUR_SLUG
```

```
db.js              → PostgreSQL connection pool and schema
routes/
  index.js         → Landing, pricing, API docs pages
  drops.js         → Create and view drops (web)
  auth.js          → Login, register, logout
  dashboard.js     → User dashboard
  api.js           → REST API endpoints
  checkout.js      → Stripe Checkout session creation
  webhooks.js      → Stripe webhook handler
middleware/
  auth.js          → User loading, auth guards, plan limits
utils/
  crypto.js        → AES-256-GCM encrypt/decrypt, slug hashing
views/             → EJS templates
public/            → Static CSS and JS
```

## Security Model

1. Each drop gets a random 24-character slug (144 bits of entropy)
2. The slug is hashed (SHA-256) for database lookup — the raw slug is never stored
3. Content is encrypted with AES-256-GCM using a key derived from the slug via PBKDF2
4. Even if the database is compromised, encrypted content cannot be decrypted without knowing the original URL
5. Passwords are hashed with bcrypt (cost factor 10-12)
6. Sessions use signed, httpOnly, SameSite cookies
